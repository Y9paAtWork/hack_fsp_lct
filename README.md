# FSP Career — сайт, аккаунты, SQLite и Jina v3

## Что находится в архиве

- React-интерфейс и готовая сборка dist.
- FastAPI backend с регистрацией, входом и сохранением профилей.
- SQLite data/fsp.sqlite3: полный импорт 66 104 резюме и 25 782 вакансий.
- Разделённые работы/проекты, вычисленные Jina-векторы и оставшаяся очередь. Точные числа готовых векторов записаны в data/checkpoint.json. Векторизация всего корпуса ещё НЕ завершена.
- SQL-схема backend/schema.sql, описание каждой таблицы DATABASE.md.
- Справочник 202 технологий, PDF/TXT-парсер и автодополнение.

## Самый простой запуск на Mac

Нужен Python 3.11 или новее. Распакуйте архив; откройте терминал в папке с README.md:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r backend/requirements.txt
python3 -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Готовая сборка включена: npm для этого запуска не нужен. Терминал оставьте открытым.

На первом запуске создайте свой аккаунт: ранее локально заполненная анкета автоматически не переносится. Пароли исходным резюме не назначены: эти записи используются как датасет, а не как активные аккаунты. Для работы с подборкой создайте отдельный аккаунт работодателя.

## Разработка интерфейса

В первом терминале запускайте backend командой выше. Во втором, из той же папки:

```bash
npm ci
npm run dev -- --host 127.0.0.1
```

Откройте http://127.0.0.1:5173. Vite отправляет /api в backend. Используйте один адрес постоянно: cookie для localhost и 127.0.0.1 различаются. При изменении frontend обновите сборку `npm run build`, если работаете через порт 8000.

## Как начать профиль заново

В анкете и на странице профиля есть «Начать анкету заново». Сбрасываются специализации, стек, работы, проекты и результат теста текущего аккаунта; имя и почта аккаунта остаются. Форма открывается с первого шага. Нормализованные работы, части текста и связанные векторы этого профиля удаляются. Другие аккаунты и датасет не затрагиваются.

«Создать другой аккаунт» сначала выходит из текущего аккаунта, затем открывает выбор роли. Для нового аккаунта нужна другая почта. Для повторного использования одной почты достаточно сбросить анкету.

## Векторизация

Модель: jinaai/jina-embeddings-v3. Локальные веса закреплены на ab036b023d30b4d1138c4c3bfa9f0c445ab455d6, код архитектуры на bd55a5ec8e6c0fb1d6c26efb4b6a4a74ce8a88d3. Проверена совместимость transformers 4.44.2 / sentence-transformers 3.4.1 / einops. Модель запускает свой код из закреплённой HF-ревизии. Веса в архив не включены; при первом запуске загружаются из Hugging Face.

В отдельном терминале:

```bash
source .venv/bin/activate
python3 -m pip install -r backend/requirements-embeddings.txt
python3 -m backend.embedding_worker --mode local --batch-size 16 --watch
```

Локальный worker получает от модели PyTorch-тензоры и преобразует их в обычные списки до передачи NumPy. Это обходит несовместимость моста PyTorch → NumPy, которая на некоторых версиях macOS/Python проявляется ошибкой `RuntimeError: Numpy is not available`.

На GPU-сервере используется CUDA, на совместимом Mac — MPS, иначе CPU. Полный корпус на CPU вычисляется долго. Для разового прогона без ожидания новых профилей уберите `--watch`. Остановка — Ctrl+C, повторный запуск продолжает по состоянию БД. Для повторения неудачных частей добавьте `--retry`. `--max-batches 10` ограничивает диагностический прогон.

Работы и проекты нового зарегистрированного кандидата получают приоритет перед датасетом. Сохранение профиля сразу создаёт записи и задания; API не ждёт тяжёлую модель. Чтобы новые данные получали векторы автоматически, worker должен работать с `--watch`. Статус виден на странице профиля.

Вариант через Jina API: задайте JINA_API_KEY только на сервере и выполните `python3 -m backend.embedding_worker --mode api --reindex --watch`. В этом режиме текст направляется в Jina; локальный режим обрабатывает его на вашем компьютере. API-ревизия помечается отдельно как jina-api-v3-managed. Используйте один режим для полного индекса: версии провайдера и локальные веса не считаются автоматически одинаковыми.

Хранение: task retrieval.passage, 1024 float32-компоненты, L2-нормализация. Длинные тексты делятся на части до 2200 символов без потери текста. Для каждой работы/проекта после обработки всех частей строится нормализованное среднее. SHA-256 текста позволяет повторно использовать совпадающие вычисления. Векторы не подменяются случайными или словарными признаками. Для пустого опыта векторы не создаются.

Для переключения режима или ревизии используйте `--reindex`: старые векторы остаются отдельными записями с собственными метаданными. Локальная модель по официальной карточке имеет CC-BY-NC-4.0: https://huggingface.co/jinaai/jina-embeddings-v3 .

## Импорт и разбиение CSV

Повторно импортировать исходные файлы можно командой:

```bash
python3 -m backend.import_data --resumes /путь/it_resumes_enriched.csv --vacancies /путь/it_vacancies_enriched.csv
```

Исходные CSV не дублируются в архиве: все их поля сохранены в raw_json каждой строки. Одинаковый файл определяется по SHA-256; повторный импорт не создаёт копии. UUID для строк воспроизводимы по виду файла, его хешу и номеру строки. Отсутствующие даты, компания или контакты не выдумываются.

Основной источник — work_experience_text, структура «должность @ компания [начало — окончание]», разделитель ||. При отсутствии полного текста используем work_experience_descriptions. Отдельные списки titles/companies не связываем по позиции: они часто дедуплицированы и имеют разную длину. Неразобранные фрагменты сохраняем и помечаем needs_review. Личные проекты выделяем по явным заголовкам «Проект:», «Projects:» и подобным в описании/дополнительной информации. Простое упоминание проекта в рабочих обязанностях не превращаем в отдельный личный проект. Поэтому это консервативное эвристическое разбиение, а не гарантированная разметка.

При импорте получено 84 550 записей: 84 134 работы, 369 явно выделенных проектов, 47 неклассифицированных фрагментов. 4 306 записей требуют ручной проверки. У 25 901 резюме work_experience_text пуст. Встречаются записи с частичной информацией в других колонках; они сохраняются по fallback-правилам.

PDF-парсер работает в браузере, читает текстовый слой, восстанавливает строки, очищает символы и применяет эвристики навыков/опыта. OCR отсутствует. Все результаты в анкете редактируемые. Подсказки берутся из technology_stack_FINAL.csv, поддерживают алиасы и выбор клавиатурой.

## Аккаунты и API

Пароли — Argon2id с индивидуальной солью. В БД хранится только SHA-256 случайного токена сессии, в браузере — HttpOnly/SameSite=Strict cookie на 7 дней. После выхода сессия удаляется. Кандидат работает только со своим профилем; доступ к набору резюме/вакансий открыт работодателю. Проверяется Origin для операций записи, есть ограничение попыток входа. Сохранение профиля атомарное и использует revision против конфликтов между вкладками.

Основные маршруты: POST /api/auth/register, POST /api/auth/login, POST /api/auth/logout, GET /api/auth/me, GET/PUT /api/profile, POST /api/profile/reset, GET /api/profile/items, GET/PUT /api/employer/profile, GET /api/candidates, GET /api/candidates/{id}, GET /api/vacancies, GET /api/database/stats.

Это локальная версия. Восстановление пароля, проверка почты, серверное выполнение кода и переписка не реализованы. Поиск списков сейчас по должности/технологии или названию вакансии; семантический поиск по векторам — отдельный следующий этап. Старые деморазделы тестов не выдаются за серверную проверку знаний. Для внешнего размещения потребуются HTTPS, FSP_COOKIE_SECURE=1 и корректные FSP_ALLOWED_ORIGINS. БД и API-ключи нельзя класть в публичную папку сайта.

## Проверки

```bash
npm test
npm run test:ui
python3 -m unittest discover -s backend/tests -v
npm run build
python3 -m backend.status
```

33 unit-теста парсера/стека/оценки, 3 UI-теста регистрации/сброса/подсказок, 9 backend-тестов авторизации, изоляции данных, импорта и векторной очереди. Подменённый encoder используется только в unit-тестах на временных БД; в приложенной БД записаны настоящие Jina-векторы. Полная векторизация корпуса не утверждается завершённой. Счётчики в checkpoint.json относятся к моменту копирования БД.
