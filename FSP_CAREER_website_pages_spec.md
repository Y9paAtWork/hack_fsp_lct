# FSP CAREER — подробное описание сайта по «сайт.docx»

**Источник:** приложенный DOCX `сайт.docx`, семь страниц со схематическими макетами экранов.  
**Тип:** дизайн-спецификация существующих макетов, а не придуманное техническое задание.  
**Правило:** описаны только видимые элементы. Там, где схема не даёт ответа, указано «Не определено». Примеры имён, компаний, баллов и зарплат — демонстрационные значения.

## 1. Состав интерфейса и общие принципы

Документ разделён на шесть частей:

| Часть исходника | Страницы DOCX | Экраны |
|---|---|---|
| Лендинг | 1 | Публичная главная |
| Регистрация кандидата | 1–2 | Данные, выбор специализаций, стек, обработка PDF, опыт/проекты |
| Тестирование | 2–3 | Каталог, общий IT-тест, тест по стеку, специализационный тест, результаты |
| Регистрация работодателя | 4 | Создание аккаунта, настройка компании |
| Кабинет кандидата | 4–5 | Главная, профиль, достижения ФСП, приглашения |
| Кабинет работодателя | 6–7 | Поиск, фильтры, выдача, профиль кандидата, приглашение, сводка |

### 1.1. Визуальный стиль

- Тёмный, почти чёрный фон; светлые надписи и тонкие прямоугольные контуры.
- Типографика в стиле терминала: моноширинные буквы, заглавные заголовки, минималистичные подписи.
- Обводки у полей, карточек, модальных окон и крупных секций; часть внешних линий пунктирная.
- Кнопки выглядят как `[ Продолжить → ]`, `[ ← Назад ]`, `[ + Добавить ]`, без тяжёлой цветной заливки.
- Компактные цветные иконки только у пунктов меню, уведомлений и медалей.
- Горизонтальные шкалы для прогресса тестов, баллов и показателей навыков.
- Большие вертикальные отступы между блоками; основные формы выровнены по центру.
- На длинных страницах показаны круглые стрелки вниз, обозначающие продолжение/прокрутку.
- Точный шрифт, HEX-цвета, размеры, тени, сетка, мобильная версия и анимации **не указаны**. Не назначать их по догадке.

### 1.2. Общая шапка и навигация после входа

**Верх:** логотип и `FSP CAREER` слева; справа колокольчик и выпадающее имя пользователя (`Аня ▼`) либо название компании (`Tech Company ▼`).

**Левое меню кандидата:** «Главная», «Профиль», «Тест», «Достижения», «Приглашения», «Отклики», «Настройки».

**Левое меню работодателя:** «Главная», «Подбор», «Кандидаты», «Приглашения», «Вакансии», «Компания», «Настройки».

Большинство внутренних экранов имеет верхнюю панель и боковое меню. При этом каталог тестов представлен также с **горизонтальной навигацией**, что нужно согласовать отдельно.

### 1.3. Повторяющиеся компоненты

- Однострочные текстовые поля и многострочные описания.
- Пароль со значком показа/скрытия.
- Выпадающие списки `▼`, чекбоксы, радиокнопки.
- Карточки специализаций с множественным выбором.
- Теги технологий, при импорте PDF — с `×` для удаления.
- Карточки работодателя/проекта/приглашения/кандидата.
- Статусы `Новое`, `Просмотрено`, `Не пройден`, `Завершён`, `Подтверждён`.
- Шкалы `N / 100`, процент заполнения профиля и `% MATCH`.
- Медали, кубки и временная шкала достижений ФСП.

## 2. Публичный лендинг (стр. 1)

### Компоновка

Полноразмерная тёмная страница: хедер, центральный hero, схема работы платформы, нижний блок преимуществ.

**Хедер:** `FSP CAREER` слева; справа `Как это работает`, `Для кандидата`, `Для работодателя`, `Войти`, `Регистрация`. Элементы текстовые, без массивных карточек.

**Главный экран:**
- двухстрочный заголовок: `НАЙДИ СВОЮ РАБОТУ / ЧЕРЕЗ СВОИ НАВЫКИ`;
- подзаголовок: `IT-платформа, где работодатели находят специалистов по подтверждённым компетенциям.`;
- две крупные равнозначные кнопки `[ Я кандидат ]` и `[ Я работодатель ]`.

**Схема процесса:** четыре прямоугольника, соединённые стрелками: `01 ПРОФИЛЬ → 02 ТЕСТ → 03 КАТЕГОРИЯ`, затем стрелка вниз к `04 ПРИГЛАШЕНИЕ`. Четвёртая карточка располагается ниже правого края схемы.

**Низ:** раздел `ПОЧЕМУ ЭТО РАБОТАЕТ` и три аргумента с галочками: `Подтверждённые навыки`, `Тестирование`, `Достижения ФСП`.

**Переходы:** по смыслу CTA ведут к регистрации соответствующей роли, `Войти` — к авторизации. Однако адреса маршрутов, форма авторизации и содержание информационных страниц в документе отсутствуют.

## 3. Регистрация кандидата (стр. 1–2)

Это многошаговый мастер `Создание профиля`. На макетах видны номера шагов `2 / 5`, `3 / 5`, `4 / 5`, внизу есть `Продолжить`, иногда `Назад`.

### 3.1. Шаг 1 — основные данные

- Верх: `LOGO` слева, `Войти` справа.
- Заголовок по центру: `Создание профиля`.
- Основная крупная рамочная форма со строками:
  1. `Имя` — пример `Анна`;
  2. `Email`;
  3. `Пароль`;
  4. `FSP ID`.
- Внизу формы `[ Продолжить → ]`.
- Под формой — ряд точек-индикаторов шагов (первая заполнена).

**Не определено:** подтверждение FSP ID, обязательность отдельных полей, правила пароля, подтверждение email и отображение ошибок.

### 3.2. Шаг 2/5 — выбор специализаций

- Хедер `LOGO | Создание профиля | 2 / 5`.
- Заголовок `Ваши специализации`.
- Подсказка: `Выберите все направления, в которых вы хотите работать. Для каждой специализации будет создан отдельный профиль.`
- Поле поиска `🔎 Поиск специализации...`.
- Сетка рамочных карточек с чекбоксами, три колонки:
  `Backend`, `Data Science`, `Frontend`, `DevOps`, `ML Engineer`, `QA`.
- В примере выбраны `Backend` и `Data Science`.
- Блок `Выбрано: 2`, ниже маркеры выбранных специализаций.
- Кнопка `[ Продолжить → ]` справа снизу.

**Важно:** поддержан множественный выбор, и **отдельный профиль создаётся для каждой выбранной специализации**. Полный перечень специализаций не показан.

### 3.3. Шаг 3/5 — технологии и PDF-резюме

- Вверху маленькие карточки выбранных специализаций `Backend`, `Data Science`.
- Активная специализация: `Backend`.
- Заголовок `Стек`, подсказка `Добавьте технологии, с которыми вы работали.`
- Большое поле со списком `Python`, `Django`, `FastAPI`, `PostgreSQL`, `Docker`.
- Под ним действие `[ + Добавить технологию ]`.
- Посередине вертикального потока разделитель `ИЛИ`.
- Альтернативная большая рамочная карточка `[ ↑ Загрузить PDF резюме ]`.
- Внутри пояснение: `Нейросеть автоматически определит технологии из вашего резюме`.
- Внизу `[ ← Назад ]`, `[ Продолжить → ]`.

**Не определено:** источник словаря технологий, выбор навыков вне специализации, требования к файлу, способ определения технологий, как обрабатывается неудачный импорт.

### 3.4. Шаг 3/5 — после обработки PDF

Отдельное состояние предыдущего экрана, заголовок `Результат обработки PDF`.

- `✓ Резюме обработано`.
- Пояснение: `Нейросеть нашла следующие технологии. Проверьте и при необходимости измените список.`
- Группа `Backend`.
- Редактируемые чипы: `Python ×`, `Django ×`, `FastAPI ×`, `PostgreSQL ×`, `Docker ×`, `Redis ×`.
- `[ + Добавить технологию ]`.
- Предупреждение: `Проверьте данные перед сохранением. Некоторые технологии могли быть определены неточно.`
- Кнопки `[ ← Изменить PDF ]` и `[ Сохранить стек → ]`.

**Принцип:** извлечённый стек нельзя молча принять за верный; у пользователя явно есть проверка и ручное редактирование.

### 3.5. Шаг 4/5 — заполнение опыта по специализации

- Хедер `Создание профиля | 4 / 5`.
- Раздел `Резюме`.
- Вкладки выбранных специализаций `Backend`, `Data Science`; активная выделена.
- Подзаголовок `Резюме для специализации: Backend` либо `Data Science`.
- Ниже несколько больших вертикальных карточек мест работы.

**Заполненное состояние Backend:** первая карточка `Компания: Яндекс`, `Период работы: 2022 — 2025`, внутри `Опыт` и `[ + Добавить проект ]`. Вторая: `VK`, `2020 — 2022`, такая же структура. После карточек `[ + Добавить место работы ]`, внизу `[ ← Назад ]` и `[ Продолжить → ]`.

**Пустое состояние Data Science:** одна карточка с полем `Компания`, двумя селекторами `Год начала` / `Год окончания`, секцией `Опыт` и кнопкой `[ + Добавить проект ]`; затем `[ + Добавить место работы ]`.

**Интерфейсная модель:** специализация → места работы → проекты внутри места работы. Периоды на примере выбираются через селекторы годов. Возможность указывать месяцы или «по настоящее время» не показана.

### 3.6. Модальное окно «Добавить проект»

По кнопке добавления проекта открывается отдельная центрированная панель:

- заголовок `Добавить проект`;
- `Название проекта` — пример `Сервис аналитики данных`;
- `Описание проекта` — большая многострочная область, пример `Платформа для анализа больших объёмов данных...`;
- `Задачи` — многострочная область с примером `Разработка API`, `Работа с PostgreSQL`, `Оптимизация запросов`;
- внизу `[ Отмена ]`, `[ Добавить проект ]`.

Отдельные поля дат проекта, стек проекта, ссылки на код **не показаны**.

### 3.7. Шаг 5/5 — отсутствует

В дизайне указано пять шагов, но **изображения пятого шага нет**. Его содержимое, действия и положение относительно тестирования не установлены. Нельзя придумывать финальный экран регистрации.

## 4. Раздел «Тестирование» кандидата (стр. 2–3)

### 4.1. Каталог / главная тестирования

На этом макете вместо бокового меню показана горизонтальная строка: `LOGO`, `Главная`, `Профиль`, `Тестирование`, `Достижения`, `Приглашения`.

В центре заголовок `Тестирование`, ниже `Чтобы сформировать ваш профиль, нужно пройти три блока.`

**Блок 01 — ОБЩИЙ ТЕСТ:**
- `Общие знания в сфере IT`;
- примерное время `~ 10–15 минут`;
- в показанном состоянии `✓ Завершён`;
- действие `[ Посмотреть результат ]`.

**Блок 02 — ТЕСТ ПО СТЕКУ:**
- `Практические задания на код`;
- перечень технологий: `Python · Django · PostgreSQL · Docker`;
- примерное время `~ 30–40 минут`;
- `○ Не пройден`;
- `[ Начать тест → ]`.

**Блок 03 — ТЕСТ ПО СПЕЦИАЛИЗАЦИИ:**
- пояснение `Этот блок проходит отдельно для каждой выбранной специализации`;
- карточка `Backend`: уровень не определён, статус `Не пройден`, `[ Начать тест → ]`;
- карточка `Data Science`: `Уровень: Junior`, статус `✓ Пройден`, `[ Посмотреть результат ]`.

Из макета не следует, что тесты обязательно блокируются до завершения предыдущих, что доступно повторное прохождение или что тест адаптивный: этих правил нет.

### 4.2. Общий IT-тест — экран вопроса

- Вверху ссылка назад `← Тестирование`.
- Заголовок `ОБЩИЙ ТЕСТ ПО IT`.
- Подпись `Проверим базовые знания в сфере информационных технологий.`
- Крупная карточка с заголовком `Вопрос 7 из 20`.
- Пример формулировки `Какой подход используется для...?` (в документе именно заглушка, а не реальное задание).
- Четыре радиоварианта: `Вариант ответа 1`, ..., `Вариант ответа 4`.
- Под карточкой горизонтальный прогресс-бар с надписью `35%`.
- Внизу `[ ← Назад ]`, `[ Следующий → ]`.

Этот конкретный макет показывает **одиночный выбор**. Интерфейсы множественного выбора/свободных ответов в исходнике не изображены.

### 4.3. Общий IT-тест — результат

Отдельная центрированная карточка:
- `Общий тест завершён`;
- большой результат `82 / 100`;
- `Базовый уровень IT-знаний: хороший`;
- список тем с галочками:
  - `Основы программирования`;
  - `Алгоритмы`;
  - `Базы данных`;
  - `Сети`;
  - `Основы разработки`;
- внизу `[ Вернуться к тестам ]`.

**Не определено:** смысл галочек (правильные темы, пройденные разделы или просто перечень), формула баллов, диапазоны оценок «хороший».

### 4.4. Тест по стеку — практическое coding-задание

- Возврат `← Тестирование`.
- Заголовок `ТЕСТ ПО СТЕКУ`.
- Подзаголовок `Ваш стек` и рамочный блок `Python · Django · PostgreSQL · Docker`.
- Раздел `Практические задания`.
- Текущий счётчик `Задание 3 из 8`.

**Рабочее поле состоит из двух соседних колонок.**
- **Левая колонка `Условие`:** текст `Напишите функцию, которая ...` и блок `Пример: input → output`.
- **Правая колонка `Ваш код`:** редактор с нумерацией строк, пример шаблона `def process(data): ...`.

**Ниже:**
- индикатор языка `Python`;
- прогресс автотестов `Тесты проходят: 7 / 10`;
- шкала с подписью `60%` (числа 7/10 и 60% не совпадают — это противоречие на макете, **не формула**);
- `[ Запустить тесты ]`;
- `[ Следующее задание → ]`.

**Точно видимое:** возможность писать код, запустить тесты и видеть результат проверок. Среда выполнения, языки, форматы hidden tests и ограничения безопасности не описаны.

### 4.5. Тест по стеку — итог

Центрированный экран:
- `Тест по стеку завершён`;
- `Результат: 76 / 100`;
- общий контейнер с четырьмя горизонтальными шкалами:
  - `Python — 86 / 100`;
  - `Django — 72 / 100`;
  - `PostgreSQL — 68 / 100`;
  - `Docker — 74 / 100`;
- надпись `Результат используется при формировании вашего профиля.`;
- `[ Вернуться к тестам ]`.

**Не определено:** формула агрегирования оценок технологий и влияние результата на профиль.

### 4.6. Тест по специализации — выбор

Экран с заголовком `ТЕСТ ПО СПЕЦИАЛИЗАЦИИ`:
- текст: `Этот тест определяет ваш уровень именно в выбранной специализации.`;
- второе пояснение: если специализаций несколько, тест проходится отдельно для каждой.
- карточка `Backend` — тест не пройден, кнопка `[ Начать → ]`;
- карточка `Data Science` — тест пройден, `Уровень: Junior`, кнопка `[ Посмотреть результат ]`.

### 4.7. Вступление перед специализационным тестом

Пример `Backend — Специализационный тест`.

Центральный инфоблок **«Что вас ждёт»**:
- задания на профессиональные знания;
- задачи на применение знаний;
- вопросы разного уровня сложности;
- примерное время `45–60 минут`;
- текст `После начала тест желательно пройти за один подход`.

Ниже отдельно:
- `Вы проходите тест для: Backend · Middle`;
- `[ Начать тест → ]`.

**Особенность:** хотя тест должен определить грейд, перед стартом уже указан `Middle`. Откуда он берётся, документ не объясняет.

### 4.8. Специализационный тест — coding-задание

- Возврат `← Тестирование`;
- `Backend · Middle`;
- `Специализационный тест`;
- строка `Задание 7 из 10`, справа таймер `Осталось: 32:14`, ниже progress bar.

**Главная карточка — две колонки:**
- **`УСЛОВИЕ`:** пример задачи о списке заказов, возврате заказов по условию X; подпункты `Входные данные`, `Ограничения`, `Примеры`, `input → output`;
- **`РЕДАКТОР КОДА`:** поле с пронумерованными строками и заготовкой `def calculate_orders(orders): ...`.

**Низ:** кнопка `[ Запустить тесты ]`, результаты проверок `✓ Тест 1`, `✓ Тест 2`, `✕ Тест 3`, `○ Тест 4`, `[ Следующее → ]`.

**Не определено:** длительность именно задачи, возможность паузы, наказание за истечение времени, способ подсчёта частичных баллов.

### 4.9. Специализационный тест — результат

- `Специализационный тест: Backend`;
- статус `Завершён`;
- по центру `Ваш уровень` и крупное `MIDDLE`;
- ниже `84 / 100`;
- карточка детализации с прогресс-барами:
  - `Архитектура — 88 / 100`;
  - `Работа с данными — 81 / 100`;
  - `Практика — 83 / 100`;
- нижний итог `Ваш профиль: Backend · Middle`;
- маркер `★ FSP verified`;
- `[ Вернуться к профилю ]`.

**Не определено:** грейдовые пороги, смысл присвоения `FSP verified` и формула итоговых 84 баллов.

## 5. Регистрация работодателя (стр. 4)

### 5.1. Регистрация аккаунта

Это отдельная центрированная вертикальная форма на тёмном фоне.

**Шапка:** `ITMATCH` (не `FSP CAREER`), затем `Регистрация работодателя`.

**Поля сверху вниз:**
1. `Название компании` — пример `Яндекс`;

## 10. Что нельзя достать из файла

Ниже — список **отсутствующих или противоречивых требований**, которые нельзя достоверно восстановить.

1. **Шаг 5 регистрации кандидата**: показано 4 из 5 шагов.
2. **Форма входа, восстановление пароля, email-подтверждение**: кнопки/ссылки есть, макетов нет.
3. **Единое название продукта**: большинство макетов `FSP CAREER`, форма работодателя `ITMATCH`.
4. **Полный справочник специализаций** и правила выбора нескольких направлений.
5. **Правила FSP ID**: обязательность, API, проверка подлинности и загрузка достижений.
6. **Процесс импорта PDF**: допустимые форматы/размеры, извлекаемые сущности, состояния ошибок.
7. **Подробная редактура резюме после регистрации**: удаление/редактирование мест работы и проектов, месяцы, текущая работа.

## 12. Заключение

Документ позволяет описать **показанные страницы, поля, визуальную композицию и основные действия**. Однако это **wireframe-набор**, а не исчерпывающее техническое задание: часть страниц отсутствует, точные правила тестирования, ранжирования и приглашений не описаны.

Всё вышеперечисленное сохранено как описание источника, **без добавления фактов от себя**. Для реализации полного продукта потребуется отдельно согласовать пункты раздела 10.
